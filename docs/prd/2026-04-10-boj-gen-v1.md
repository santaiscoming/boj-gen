# BOJ Gen v1 PRD

## 1. 문서 개요

- 문서명: BOJ Gen v1 Product Requirements Document
- 작성일: 2026-04-10
- 대상 제품: `boj-gen`
- 목표: 백준 문제 풀이를 시작할 때 문제별 템플릿과 예제 입력을 자동 생성해, 사용자가 입력을 수기로 복사하지 않도록 한다.

## 2. 배경

백준 문제를 풀 때 사용자는 다음과 같은 반복 작업을 수행한다.

- 문제 번호를 기준으로 작업 디렉터리를 직접 생성한다.
- 사용하는 언어에 맞는 시작 코드를 수기로 작성하거나 복사한다.
- 문제 페이지의 예제 입력을 복사해 `input.txt` 같은 로컬 테스트 파일에 붙여 넣는다.

이 과정은 문제 풀이 자체와 무관한 보일러플레이트 작업이며, 반복 횟수가 많을수록 피로가 누적된다. 특히 여러 언어를 병행하는 경우 템플릿 관리 비용도 커진다.

`boj-gen` 은 이 반복 작업을 CLI 한 번으로 줄여, 사용자가 바로 알고리즘 풀이에 들어갈 수 있도록 한다.

## 3. 제품 목표

### 3.1 핵심 목표

- 사용자가 `boj` 명령어 한 번으로 문제용 작업 폴더를 생성할 수 있어야 한다.
- 선택한 언어에 맞는 제출 가능한 시작 템플릿을 자동 생성해야 한다.
- 문제 페이지에서 첫 번째 예제 입력을 가져와 로컬 테스트용 `input.txt` 를 자동 생성해야 한다.
- 로컬 실행과 백준 제출 사이에서 별도 코드 수정이 없어야 한다.

### 3.2 성공 기준

- 사용자가 문제 번호만 알고 있어도 10초 이내에 풀이를 시작할 수 있다.
- 생성된 템플릿은 언어별로 즉시 컴파일 또는 실행 가능해야 한다.
- 예제 입력 수기 복사 과정이 제거되어야 한다.
- 언어 미지정 시에도 사용자 안내만으로 생성 흐름을 완료할 수 있어야 한다.

### 3.3 비목표

- 여러 문제를 한 번에 생성하는 기능
- 예제 입력 여러 개를 모두 저장하는 기능
- 사용자 설정 파일 기반의 기본 경로/기본 언어 관리
- 원격 로그 수집
- 문제 본문 전체를 마크다운으로 저장하는 기능

## 4. 대상 사용자

- 백준에서 문제를 반복적으로 푸는 개인 개발자
- 로컬에서 빠르게 테스트한 뒤 동일 코드를 제출하고 싶은 사용자
- Rust, C++, Java, JavaScript, Python 중 여러 언어를 사용하는 사용자

## 5. 사용자 문제 정의

현재 사용자는 문제 하나를 시작할 때마다 아래 문제를 겪는다.

- 언어마다 시작 파일을 수기로 만들고 기본 입력 코드를 복사해야 한다.
- 예제 입력을 복사하는 과정이 번거롭고 실수 가능성이 있다.
- 로컬 테스트용 코드와 제출용 코드가 달라져 제출 전에 코드를 다시 수정해야 하는 경우가 생긴다.
- 작업 폴더 이름과 파일 이름 규칙이 매번 달라져 정리 일관성이 떨어진다.

## 6. 제품 원칙

- CLI 는 짧고 단순해야 한다.
- 생성 결과는 즉시 사용 가능해야 한다.
- 기본값은 실용적이어야 하며, 사용자 선택이 꼭 필요한 시점에만 입력을 요구한다.
- 실패 시 부분 생성보다 일관된 중단이 우선이다.

## 7. 사용자 시나리오

### 시나리오 A: 언어를 명시해 바로 생성

1. 사용자가 `boj 11066 --lang rust` 를 실행한다.
2. CLI 는 문제 페이지에서 제목과 첫 번째 예제 입력을 가져온다.
3. 현재 디렉터리에 `11066_파일_합치기/` 폴더를 만든다.
4. `main.rs` 와 `input.txt` 를 생성한다.
5. 사용자는 템플릿 파일을 열고 풀이를 작성한다.

### 시나리오 B: 언어를 지정하지 않고 대화형 선택

1. 사용자가 `boj 11066` 을 실행한다.
2. CLI 는 지원 언어 목록을 보여주고 번호 입력을 받는다.
3. 사용자가 올바른 번호를 입력하면 나머지 생성 과정을 진행한다.
4. 사용자가 잘못된 값을 입력하면 재입력을 요청한다.
5. 3회 연속 실패 시 에러 메시지를 출력하고 종료한다.

### 시나리오 C: 이미 동일 폴더가 존재

1. 사용자가 기존에 생성한 문제 폴더가 있는 상태에서 다시 같은 명령을 실행한다.
2. CLI 는 덮어쓸지 사용자에게 묻는다.
3. 사용자가 동의하면 이번 실행에서 관리하는 파일만 다시 생성한다.
4. 사용자가 거절하면 아무 것도 변경하지 않고 종료한다.

## 8. 기능 요구사항

### 8.1 CLI 명령 형식

- 기본 명령 형식은 아래 둘을 지원한다.
  - `boj <problem_number> --lang <language>`
  - `boj <problem_number> -l <language>`
- `problem_number` 는 백준 문제 번호를 의미한다.
- `language` 는 아래 값 중 하나다.
  - `rust`
  - `cpp`
  - `java`
  - `javascript`
  - `python`

### 8.2 언어 미지정 시 대화형 선택

- `--lang` 또는 `-l` 이 없으면 지원 언어 목록을 사용자에게 보여줘야 한다.
- 입력 방식은 목록 번호 기반이어야 한다.
- 허용하지 않는 값이 입력되면 에러 메시지와 함께 재입력을 받아야 한다.
- 최대 재시도 횟수는 3회다.
- 3회 실패 시 종료 코드 1로 종료해야 한다.

### 8.3 문제 페이지 크롤링

- 대상 페이지는 `https://www.acmicpc.net/problem/{problem_number}` 형식이어야 한다.
- v1 에서 크롤링 대상은 아래로 제한한다.
  - 문제 제목
  - 첫 번째 예제 입력
- 요청 실패 또는 HTML 파싱 실패 시 내부적으로 최대 3회 재시도해야 한다.
- 재시도 후에도 실패하면 생성을 중단해야 한다.
- 실패 원인과 재시도 결과는 `stderr` 로 출력해야 한다.

### 8.4 디렉터리 생성 규칙

- 출력 위치는 명령을 실행한 현재 디렉터리다.
- 폴더 이름은 `{문제번호}_{문제제목}` 형식을 사용한다.
- 제목 정규화 규칙은 아래를 따른다.
  - 공백은 `_` 로 치환한다.
  - 파일명에 사용할 수 없는 예약 문자는 `_` 로 치환한다.
  - 연속된 `_` 는 하나로 축약한다.
  - 한글, 영문, 숫자는 유지한다.

### 8.5 생성 파일 규칙

- 생성 파일은 문제 폴더 하위에 위치해야 한다.
- 항상 `input.txt` 를 생성해야 한다.
- 언어별 소스 파일명은 아래를 사용한다.
  - Rust: `main.rs`
  - C++: `main.cpp`
  - Java: `Main.java`
  - JavaScript: `main.js`
  - Python: `main.py`

### 8.6 언어별 템플릿 요구사항

- 모든 언어 템플릿은 아래 조건을 만족해야 한다.
  - 로컬 실행 시 `input.txt` 가 있으면 파일 입력을 우선 사용한다.
  - `input.txt` 가 없으면 표준 입력을 사용한다.
  - 백준 제출 시 별도 수정 없이 제출 가능해야 한다.
  - 사용자는 풀이 로직만 추가하면 되도록 최소 보일러플레이트를 포함해야 한다.

#### Rust

- `input.txt` 파일이 존재하면 파일을 읽고, 없으면 `stdin` 을 읽어 토큰화해야 한다.
- 현재 예시 패턴처럼 제출 가능한 구조를 유지해야 한다.

#### C++

- `ifstream("input.txt")` 가 열리면 파일 입력을 사용하고, 아니면 `cin` 을 사용해야 한다.
- 표준적인 `main` 함수 형태여야 한다.

#### Java

- 클래스명은 `Main` 이어야 한다.
- `input.txt` 가 있으면 파일 입력 스트림을 사용하고, 아니면 `System.in` 을 사용해야 한다.
- 백준 제출 제약에 맞는 단일 파일 구조여야 한다.

#### JavaScript

- Node.js 환경 기준이어야 한다.
- `input.txt` 가 있으면 파일을 읽고, 아니면 파일 디스크립터 0에서 읽어야 한다.

#### Python

- `input.txt` 가 있으면 파일을 열고, 아니면 `sys.stdin.buffer` 를 사용해야 한다.
- 기본 엔트리포인트는 단일 파일이어야 한다.

### 8.7 기존 경로 존재 시 처리

- 동일한 문제 폴더가 이미 있으면 사용자에게 덮어쓸지 확인해야 한다.
- 동의 시 이 도구가 관리하는 생성 대상 파일만 다시 생성한다.
- 비동의 시 아무 것도 변경하지 않고 종료한다.

## 9. 비기능 요구사항

### 9.1 사용성

- 한 문제 생성에 필요한 필수 입력은 문제 번호와 언어뿐이어야 한다.
- 언어를 명시하지 않아도 사용자가 문맥 없이 완료할 수 있을 만큼 안내가 명확해야 한다.

### 9.2 일관성

- 같은 문제 번호와 제목에 대해 항상 동일한 폴더/파일 규칙을 사용해야 한다.
- 언어별 템플릿 구조는 다르더라도 사용 목적은 동일해야 한다.

### 9.3 안정성

- 크롤링 실패 시 부분적으로 파일이 생성되면 안 된다.
- 입력 검증 실패는 명확한 메시지와 함께 종료되어야 한다.

### 9.4 성능

- 일반적인 네트워크 상태에서 한 번의 문제 생성 흐름은 수 초 내 완료를 목표로 한다.
- 재시도 정책은 사용자 체감이 과도하게 길어지지 않도록 짧은 backoff 를 사용한다.

### 9.5 유지보수성

- CLI 파싱, 크롤링, 템플릿 생성, 파일 생성 로직은 모듈 단위로 분리되어야 한다.
- 크롤링 HTML 파싱은 fixture 기반 테스트가 가능해야 한다.

## 10. 예외 및 실패 처리

### 10.1 잘못된 문제 번호

- 문제 번호 형식이 잘못되었거나 페이지가 존재하지 않으면 생성을 중단한다.
- 사용자에게 문제를 확인할 수 없다는 메시지를 출력한다.

### 10.2 네트워크 실패

- 요청 실패 시 최대 3회 재시도한다.
- 최종 실패 시 `stderr` 에 실패 사유를 출력하고 종료한다.

### 10.3 HTML 구조 변경

- 제목 또는 예제 입력을 찾지 못하면 파싱 실패로 간주한다.
- 이 경우도 재시도 후 중단한다.

### 10.4 인터랙션 실패

- 언어 선택에서 3회 연속 실패 시 강제 종료한다.

### 10.5 파일 시스템 충돌

- 덮어쓰기 거절 시 변경 없이 종료한다.
- 생성 중 필요한 디렉터리를 만들 수 없으면 에러를 출력하고 종료한다.

## 11. 사용자 출력 메시지 원칙

- 정상 흐름에서는 현재 무엇을 생성했는지 요약 메시지를 출력한다.
- 실패 시에는 아래를 포함한다.
  - 어떤 단계에서 실패했는지
  - 재시도 여부와 횟수
  - 최종 종료 이유
- 메시지는 한국어 기준으로 작성한다.

## 12. 수용 기준

아래 조건을 모두 만족하면 v1 요구사항을 충족한 것으로 본다.

1. `boj 11066 --lang rust` 실행 시 현재 디렉터리에 `11066_파일_합치기/` 가 생성된다.
2. 생성 결과에 `main.rs` 와 `input.txt` 가 포함된다.
3. `input.txt` 에는 문제 페이지의 첫 번째 예제 입력이 저장된다.
4. 생성된 `main.rs` 는 `input.txt` 가 있을 때 파일 입력으로 로컬 실행 가능하다.
5. 동일 파일을 별도 수정 없이 백준 제출용으로 사용할 수 있다.
6. `boj 11066` 실행 시 언어 목록이 표시되고 번호 입력을 통해 생성 가능하다.
7. 잘못된 언어 선택을 3회 반복하면 종료 코드 1로 종료한다.
8. 크롤링 실패 시 어떤 파일도 생성되지 않는다.
9. 동일 폴더가 이미 있으면 덮어쓰기 확인이 출력된다.
10. C++, Java, JavaScript, Python 에 대해서도 동일한 규칙의 템플릿이 생성된다.

## 13. 구현 범위 제안

### v1 필수 범위

- CLI 인수 파싱
- 언어 선택 프롬프트
- 백준 문제 페이지 크롤링
- 현재 디렉터리 기준 문제 폴더 생성
- 언어별 템플릿 생성
- `input.txt` 생성
- 에러 메시지 및 재시도 처리

### v1 이후 후보

- 여러 예제 입력을 각각 별도 파일로 저장
- 사용자 설정 파일 지원
- 기본 언어 기억 기능
- 문제 본문/출력 예제 저장
- 여러 문제 번호 일괄 생성

## 14. 기술 메모

- 구현 언어는 현재 저장소 기준 Rust 를 사용한다.
- 바이너리 이름은 `boj` 로 제공하는 방향이 적절하다.
- HTTP 요청과 HTML 파싱은 안정적인 Rust 생태계 라이브러리를 사용한다.
- 테스트는 단위 테스트와 통합 테스트를 함께 구성한다.
